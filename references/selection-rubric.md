# Selection Rubric

Return one icon only.

## Hard gates

Reject a candidate unless all are true:

1. The current License State permits the intended use.
2. The target stack can integrate it reliably.
3. Its exact identity and usable code or asset path are verified.
4. It remains legible at the target size and state.
5. It can meet the interface's accessibility needs.

## Ranking

Rank eligible candidates in this order:

1. Semantic accuracy.
2. Consistency with the Existing Icon System: library, geometry, stroke, corners, color, size, and motion.
3. Legibility at the target size.
4. Fit for the required state or motion.
5. Integration and maintenance cost.
6. Visual preference.

Do not mix libraries within one navigation, toolbar, or action group merely because another library has a more attractive individual icon.

## Ambiguity

Use surrounding labels, destination, current state, and expected result to distinguish actions such as save vs download, refresh vs synchronize, close vs delete, share vs export, settings vs tune/filter, and favorite vs bookmark.

When the difference changes what the control promises, ask one focused question. When a conventional generic glyph is accurate, choose it directly.

If no accurate candidate exists, do not silently substitute emoji, text characters, or a newly drawn SVG. Report the semantic gap; new icon design is a separate task.
